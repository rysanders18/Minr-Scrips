# irodori

A colour-burst cutscene for the Minr server, built from Minecraft `block_display` entities. Thirty-five displays, each a differently coloured block, sit at one anchor beside an armour stand. The animation throws them out to a ring and flies them back onto the stand in three overlapping passes, while the stand's dyed armour fades through a colour journey, a particle helix orbits it, and a rainbow wheel sweeps the floor as a finale. The MSC namespace is `irodoriAnimation`; the colour tables it uses are generated by `irodori_gradient.py`.

## How it works

- **Tag index = colour index.** `summonBlockDisplays` spawns one display per entry of `blockColors` tagged `iro<i>`. Every other function addresses displays by that tag, so the array order is the contract (`irodoriAnimation.nms`).
- **Two alternating passes.** `scatterBlockDisplays` snaps each display to a random point on the ring at scale 0 with a random tumble and `interpolation_duration 0`, so the jump is never seen. `moveBlockDisplays` interpolates each one back to the stand at full scale, sprays its block particle and plays a chime. The driver `irodoriAnimation.msc` schedules them at t=0/36/72/106/142 ticks, firing every pass after the first with `@console` so the ring empties while the previous burst is still in flight. Console has no world context, which is why every command is wrapped in `execute in {{animWorld}}`.
- **Continuous chime pitch.** Each pass ramps pitch linearly from `pitchStart` to `pitchEnd`, and the driver hands the three passes adjoining windows (0.5-0.9, 0.9-1.3, 1.3-1.7). The chime therefore climbs across all 105 arrivals instead of restarting per pass.
- **Aiming at a moving target.** `shakeStand` lifts the stand on a smootherstep-eased triangle. `standRiseAt(tick)` is the single source of truth for that height, and `moveBlockDisplays` aims each display at where the stand *will* be on the tick that display lands, so the two cannot drift apart.
- **Targeted field writes.** `vanishBlockDisplays` writes only `transformation.scale`; the compound `transformation:{...}` form decomposes the matrix and would yank every display back to the anchor as it shrank.
- **Spiral helix.** `spiralParticles` emits `dust_color_transition` particles orbiting the stand. Three cycles (orbit, climb, radius breathing) run on unequal periods so the path never repeats, extra arms join at fixed progress points, speed scales on a squared curve, and the orbit draws inward. Each particle transitions to the colour `spiralLead` ticks ahead, so the motes carry the colour the armour is about to become.
- **Finale.** `finale` fires a bang on the stand, then draws rainbow spiral arms outward on an ease-out curve before they split into smaller whirls that wind back to nothing. The room is 7 blocks across, so a hard radius cap of 3.5 blocks is enforced in the constants.

### Colour gradient (`irodori_gradient.py`)

The armour fade is 240 frames, one per tick, with separate chestplate, leggings and boots tables. Colours are authored in OKLCH rather than RGB or HSV: interpolating in RGB drags a hue sweep through grey every time it crosses between primaries, whereas OKLCH keeps chroma and perceived lightness even. The chestplate keyframes jump around the wheel (near-black, navy, gold, plum, green, azure, orange, red); each consecutive pair is a recognised harmony, alternating cool and warm. Each colour is held and the move happens inside the middle 35% of its segment with smootherstep easing, so the sequence reads as cut colours rather than a spectrum wipe; a chroma dip proportional to hue distance keeps the pass-through from reading as a colour of its own. Chroma is specified as *vibrance*, a fraction of the maximum chroma sRGB can hold at that lightness and hue, because the gamut's width varies enormously around the wheel. Leggings and boots are derived by tier: lifted toward light by a fraction of the remaining headroom, softened, and rotated up to 50 degrees round the wheel so the three pieces read as one analogous set. Out-of-gamut colours are brought back by reducing chroma only, never by clipping channels (which would shift the hue). The same script emits the spiral colours (floored in lightness so a particle is never a dark speck) and the finale's 120-band hue wheel, each band drawn at its own gamut-cusp lightness.

## Layout

| Path | Role |
|---|---|
| `irodoriAnimation.nms` | Namespace: tunables (anchor, timings, spiral and finale constants), `blockColors`, function signatures |
| `irodoriAnimation/irodoriAnimation.msc` | Driver; the tick timeline |
| `irodoriAnimation/summonBlockDisplays.msc` | One-time world setup |
| `irodoriAnimation/scatterBlockDisplays.msc`, `moveBlockDisplays.msc`, `vanishBlockDisplays.msc` | The passes |
| `irodoriAnimation/shakeStand.msc`, `standRiseAt.msc` | Stand lift |
| `irodoriAnimation/dyeArmourGradient.msc`, `spiralParticles.msc`, `finale.msc` | Armour fade, helix, ending; contain generated colour tables |
| `irodori_gradient.py` | OKLCH generator that rewrites those tables in place |

## Running it

Run `summonBlockDisplays()` once in-world, then `/function execute irodoriAnimation::irodoriAnimation(Player("Name"))`. To retune colours, edit `KEYFRAMES` or the `TIER` constants in `irodori_gradient.py` and run `python irodori_gradient.py`; it replaces the `@define String[]` tables in the three `.msc` files.

## Notes

- Changing `stepTicks` changes the length of a pass (35 displays x 2 ticks = 70), so the driver's `@delay` schedule has to be re-timed with it.
