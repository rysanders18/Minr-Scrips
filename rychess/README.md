# rychess

A chess engine and a physical, click-to-play chess board, both written in MSC for
the Minr Minecraft server. The engine is a fail-soft negamax alpha-beta search
with quiescence and an incrementally maintained evaluation. The board is a set of
`block_display` entities that slide pieces with Minecraft's built-in
interpolation, and the opponent is a `mannequin` (see `../mannequin`) that
physically walks up to the board, "thinks", and moves the piece.

MSC has no bitwise operators, no classes, no threads and a per-tick execution
budget, so most of the engineering here is about fitting a real engine into
those constraints. `sim/` contains a line-for-line JavaScript port of the engine
plus an exhaustive search for the shortest checkmate against it.

## Layout

| Path | Role |
|---|---|
| `rychess.nms` | Namespace manifest: per-player state, piece-square tables, board textures, piece base translations, and every function signature |
| `rychess/<name>.msc` | One function per file. The first comment block of each file is its spec |
| `rychess/__init__.msc` | Summons the board and all 32 piece clusters (generated; one line per entity) |
| `rychess/# *.msc` | Standalone in-game scripts bound to buttons/regions (reset, leave, enter) |
| `rychess/test*.msc` | Self-tests run in-game: move codec, perft, make/unmake round trip, recursion and loop semantics |
| `sim/` | JavaScript port, self-tests, tournament and UCI harness, shortest-mate search ([sim/README.md](sim/README.md)) |
| `../tools/scale_board.py` | Rewrites the transformation matrices in `__init__.msc` so the board scales from one constant |

## Engine

**State** is per-player (`relative` in MSC): `board[64]`, `sideToMove`,
`castling` (bitmask 1=WK 2=WQ 4=BK 8=BQ), `epSquare`, `halfmoveClock`, a
1000-entry `undoStack`, and `runningScore`, the material-plus-PST evaluation
kept up to date by `pieceContrib` deltas on every make/unmake.

**Moves are one packed Int.** Without bit operators, `moveEncode` packs
`from + to*64 + promo*4096 + flags*32768` and the accessors decode with division
and modulo. Flags: quiet, capture, double push, en passant, castle K, castle Q.

**Move generation** is per piece (`genPawnMoves`, `genKnightMoves`, ...) into
`genAllPseudoLegal`, then `genLegalMoves` filters by make/unmake plus `inCheck`.
Castling through check is filtered in `genKingMoves` itself because the
post-filter only sees the landing square.

**Search.** `chooseMove` is the root. `searchInner` is fail-soft alpha-beta
with a breadth cap (`maxBranches`) chosen to keep server tick rate intact, and
`qsearch` is a recapture-only quiescence search so the leaf evaluation is not
taken mid-exchange. The root loop yields one server tick (`@delay 1`) between
moves so the search never monopolises the tick thread.

That yield creates a real concurrency problem: while the engine is searching,
`makeMove` flips `sideToMove`, so a player click could slip in and mutate the
position mid-search. `humanCanMove` is a per-player gate set only when the
non-simulated state is genuinely the human's turn. Its comment in
`rychess.nms` documents every set and clear point.

**Evaluation** is material plus Michniewski piece-square tables, side-to-move
relative, with a small bonus for pawns with empty adjacent files.

**Perft** (`perft`, `testPerft`) and a make/unmake round-trip test exist because
a packed-move engine with a hand-rolled undo stack is exactly the kind of code
that goes wrong silently.

## Variant rules

This is deliberately not standard chess. Pawns may move or capture one square
sideways, may double-push from any rank, and auto-promote to a queen. The
sideways rule feeds through move generation, `isSquareAttacked` and the
evaluation term. `noticeVariantRules` and the `chatRule*` scripts explain the
rules to the player in-game. `sim/engine_standard.js` is the same engine with
standard rules, used for comparison games.

## Board

Each piece is a cluster of `block_display` passengers sharing a tag
`rychess<rankTag><fileTag><NN>`; the 64 squares are interaction entities tagged
`rychessboard<R><F>` that double as click targets and highlight surfaces.
`pieceCodeAt[player]` tracks which piece sits on which square in lockstep with
`board[player]`, and `applyMoveVisually` is called only from the play and engine
entry points, never from inside the search.

Moving a piece writes only `transformation.translation` on each entity
(`applyTransform`). That single choice triggers Minecraft's interpolation for
the slide and preserves each entity's rotation and scale, which is what keeps
the multi-entity pieces from collapsing to a point. Captured pieces are sunk
below the slab (`sinkPiece`) rather than killed so `newGame` can raise them
again.

The whole board is scaled by one constant `m` at the top of `__init__.msc`.
Every matrix entry is templated `{{value*m}}f` (generated by
`tools/scale_board.py`), which scales magnitude while preserving rotation.

## Opponent performance

`engineMove` layers a choreographed performance over the search: a random
"didn't notice it's my turn" delay, the mannequin stopping its idle recording,
walking to the midpoint of the move with a little yaw jitter, a contemplation
pause (sometimes leaning in), then the move, with sound cues for select, move,
capture, check and checkmate. If the engine's evaluation swings by more than two
pawns between turns, a chat reaction fires (`chatTaunt`, `chatCope`).

## Running it

Import `rychess.nms` and the `rychess/` functions on the server, run
`rychess::__init__` once to summon the world, then bind `# enterRegion.msc`,
`# resetButton.msc` and `# Leave Button.msc` to the room. Tests are invoked
in-game, for example:

```
/function execute rychess::testPerft(Player)
```

For the JavaScript port: `cd sim && node selftest.js`, then
`node mate.js [maxHumanMoves] [humanColor]`.
